## Decisions, constraints, and why

| ID | Approved staging baseline | Reason / operational enforcement |
| --- | --- | --- |
| MED-DEC-01 — Formats | **Static JPEG/PNG/WebP only.** Reject GIF, SVG, HTML, PDF, executables, animated WebP and other polyglot/active content. Extension, declared MIME and signature must agree, followed by **trusted full image decode and clean re-encode**. | Image-only CMS milestone, low surface area; magic bytes alone are not safe decoding |
| MED-DEC-02 — Bounds | **10 MiB compressed bytes/file** (10,485,760 bytes), **25,000,000 decoded pixels**, **8192 px per dimension**, **4096 async chunks/request**, **30 s receive deadline**. Refuse missing/invalid/over-budget lengths. | Preserves normal photographs without large spikes; enforce both streaming and actual decoded dimensions; timeouts cannot be replaced by chunk budget |
| MED-DEC-03 — Scanner | Private isolated **ClamAV-compatible scanner service** plus full trusted decode/re-encode removing EXIF/GPS. Require authenticated, versioned *clean* attestation over original SHA-256, object key, scope, scanner version and expiry (15 min). **No provider or secret currently provisioned:** scanner availability is FALSE, so publishing and serving MUST be denied. Scan outage/timeout/inconclusive/positive is fail-closed. | No false malware-clean claims from magic bytes, HTTP 200, or human review. Provider choice is a technical standard/adapter, not a statement that a working scanner exists. Run the scanner outside the Worker or in a separately isolated service |
| MED-DEC-04 — Permissions | CMS **admin/editor**: upload; CMS **reviewer/admin**: approve or reject only scan-passed/quarantined items as appropriate; CMS **admin only**: publish, revoke/delete and retention overrides; CMS **viewer**: view approved metadata/derivatives only. Newsroom-only roles receive **no CMS Media privilege**. Match active actor, asset scope/owner in D1 for each request, audit sensitive actions, protect Origin/CSRF. | Reuses seven existing role codes without IAM schema change. For first milestone, reviewer approval and admin publication remain distinct; no client role or scope accepted as proof |
| MED-DEC-05 — Privacy / retention | R2 **private only**, no `r2.dev` or direct client URLs. Server-controlled derivative delivery only once **AVAILABLE** and scan+decode+approval verified; raw originals never publicly served. Reservations expire **1 h**, unfinished quarantine **7 d**, failed/rejected quarantine **2 d**, revoked object purge within **24 h**, minimally identifiable D1 tombstone **90 d**; approved assets retained until explicit removal or lawful hold. | Safe defaults with bounded storage and immediate read denial on revocation; object deletion cannot precede verification of references/audit. Legal holds and preservation requests override scheduled deletion through separate approved control |
| MED-DEC-06 — Quotas/privacy | Actor **20 uploads/h**, scope **200 uploads/day** and **1 GiB incoming/day**, **5 GiB scope stored** and **2 concurrent uploads/actor**. Atomic D1 accounting, no best-effort local in-memory counter as the sole defense. Strip EXIF/GPS, use opaque UUID object keys, limit error logs to safe codes and IDs. | Avoid cost/abuse surprises while leaving ordinary CMS editing practical. Counts are adjustable only through a reviewed policy version |
| MED-DEC-07 — Recovery | D1 idempotency uniqueness per `(scope, actor, SHA256(token))` + reservation, private R2 `quarantine/{scope-id}/{UUID}`, and compare-and-swap `(status,revision)` with audit. A D1/R2 operation is **not one atomic transaction**: reconcile orphan objects and stale reservations under bounded leases. No retry can create a second logical asset; rollback is non-serving even when R2 deletion fails. | Prevents false "published" state or secret object exposure after partial writes |

## Canonical state machine and service invariants

`QUARANTINED → SCAN_PENDING → SCAN_PASSED → REVIEW_APPROVED → AVAILABLE`. A positive scanner/decoder attestation, verified by a trusted backend **inside** the authorization + D1 transition path, is mandatory. Failures go to non-serving `SCAN_FAILED` or `REJECTED`; active or approved material can move to `REVOKED`, then `DELETED`. Refuse unexpected edges; D1 CAS must update exactly one row and record the same effective revision in audit; reject stale expected revisions.

**Every byte serving path** (even admin) must check authoritative D1 scope, `AVAILABLE`, attestation freshness and non-revoked status, and must return a re-encoded derivative, not the private original. Cache must not retain stale content after revocation. The pure RBAC and stream helpers are NOT sufficient to satisfy this; identity must be verified by the Worker at ingress and checked against D1 current active roles. Content-size safeguards must be performed before R2 write and during streaming; decoded dimensions must be verified by the decoder.

**Backpressure and scanning:** 10 MiB single-object R2 PUT is sufficient; multipart is NOT needed for first milestone. Any temporary object stays in the private quarantine namespace and is never advertised. Upload quota/limits, idempotency, object write, scanner and cleanup must have separate failure-injection tests.

## Safe rollout sequence (no implicit release)

1. **Approved now:** policy decisions MED-DEC-01..07 and code/test baseline, architectural D1/R2 interface and test-first preparation on GitHub.
2. **Before staging WRITE:** forward-only D1 migration reviewed against current live schema, source-sha CI, D1 bookmark/rollback plan, working private bucket binding and per-action genuine Access/native identity; operations Issue #30 intermittent 503 must be acknowledged for pilot.
3. **Before any publish/serve:** scanner deployed/configured with authenticated service-to-service attestation, independently secured image decoder and EXIF stripping, verified D1 CAS/rate quotas, private R2 read restrictions, cleanup reconciler, mock/fault-injection + authorized staging negative/browser E2E.
4. **Before production:** separate explicit Owner release decision, full security and data-retention review, release-branch CI, cleanup rollback drill and SRS decision independently. Current **production remains HOLD** and has no Media R2 binding.

## Retention and incident handling

- Reconciler checks bounded batches by age; never unilaterally delete an AVAILABLE asset or media referenced by published CMS content. For legal hold, set an authorized D1 flag and suspend object removal with audit.
- A failed R2 delete is a non-serving tombstone with queued retry, **not** "DELETED". Treat excessive 503 as an independent staging operations incident [#30](https://github.com/ntdung-tds/iaict-portal/issues/30).
- No scanner provider keys, credentials, raw filenames or EXIF payloads in public GitHub/PCS/CI logs or screenshot files. Private QA media evidence is in Drive only.
